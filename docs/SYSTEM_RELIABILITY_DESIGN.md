# SSTV Aggregator Webシステム 設計・信頼性・高速化の工夫まとめ

本ドキュメントは、SSTV TurboPNG Aggregator Webシステムにおいて、システムがエラーを起こさず、高速かつ安全に動作するために施されたアーキテクチャ上の工夫と信頼性設計をまとめたものです。

---

## 1. パフォーマンス最適化・タイムアウト防止設計

### 1.1 高速SQL直接集計（ミリ秒レスポンス化）
- **課題**: 復元画面を開くたびに全タイルの全パケット・ビット列をPythonの多重ループで計算していたため、サーバー負荷が増大しタイムアウトや読み込みフリーズ（「計算中...」で停止）が発生していました。
- **改善**: 
  - 復元率・パケット数・欠損タイルの検出を、SQLiteの直接集計クエリ（`COUNT(DISTINCT tile_y || '_' || tile_x)` や `GROUP BY tile_y, tile_x`）に変更。
  - 数千〜数万件のパケットが存在しても **1ミリ秒未満** でレスポンスを返せるようになり、Gunicornワーカーのブロッキングを完全に解消しました。

### 1.2 データベース複合インデックス & WALモード
- **PRAGMA journal_mode=WAL**: SQLiteの先行書き込みログ（WAL）を有効化し、複数ユーザーからの同時読み込みと書き込みのロック競合を防止。
- **インデックス追加**:
  - `(image_id, tile_x, tile_y, payload_length)`
  - `(image_id, user_id)` / `(user_id, image_id)`
  - `(image_id, tile_y, tile_x)`
  これにより、特定ユーザーの履歴抽出や画像ごとのタイル検索が劇的に高速化されました。

## 2. 並行処理・同時アクセス競合耐性

### 2.1 ファイル名の衝突（コリジョン）防止
- **課題**: 複数ユーザーが同時に音声をアップロードした際、ログファイル名や音声ファイル名が秒単位のタイムスタンプのみだとファイルの上書き・破損が発生していました。
- **改善**:
  - デコーダーログ名に **マイクロ秒（`%f`）＋ UUID 6桁**（例: `%Y%m%d_%H%M%S_%f_{uuid}`）を付加。
  - アップロード音声ファイルも `{job_id}_{secure_filename}` で保存し、処理完了後に自動クリーンアップ（削除）することで、ディスク容量の枯渇とファイル衝突を防止。

### 2.2 非同期ジョブ管理（SSE / ポーリング）
- 音声デコードなどの重い処理をバックグラウンドスレッド（`job_manager`）で実行し、フロントエンドとは Server-Sent Events (SSE) または進捗APIで通信。
- Nginx / Gunicorn のHTTPリクエストタイムアウト（30秒〜60秒）を確実に回避。

## 3. アカウント・ユーザーデータの完全分離

### 3.1 ネットワーク全体データと個人貢献データの分離
- **全体統合画像（ALL）**: `restored_ID_XXXX.png`（全ユーザーのパケットを集約した多数決画像）。
- **ユーザー個別画像（YOU）**: 
  - **「今回の音声のみ」**: `user_{user_id}_ID_XXXX.png`（直近のアップロードで得られたパーツ）。
  - **「これまでの合計」**: `user_cumulative_{user_id}_ID_XXXX.png`（過去を含めユーザーが投稿した全パケットの合成画像）。
- **未投稿アカウントへの配慮**:
  - ユーザーが未投稿の画像IDに対しては、`user_has_data = False` を厳密に判定し、プレースホルダー画像（「まだ投稿していません」）を表示。他人のパーツ画像が誤って表示されることを完全に防止。

### 3.2 相互フォールバック付き画像ローダー
- フロントエンド（JavaScript）において、セッション画像や累積画像の読み込み失敗時（`onerror`）に相互フォールバック（連鎖的エラーハンドリング）を実装し、画像が表示されないバグを防止。

## 4. 認証・セキュリティ設計

### 4.1 セッション管理とアクセス保護
- **セッション有効期限**: `session.permanent = False` を徹底し、ブラウザ終了時に認証セッションを破棄。未ログイン時は必ず `/login` へ強制リダイレクト。
- **管理者権限の分離**: `/admin` や画像一括クリーンAPI（`POST /admin/delete_images`）は、管理者（`is_admin`）以外からのリクエストを `403 Forbidden` で確実に遮断。

### 4.2 管理者向け選択クリーンアップ
- 誤ったデータやテスト画像を安全にクリーンできるように、管理画面からチェックボックスで選択して一括削除できる機能を実装。
- DBのパケットレコードだけでなく、ディスク上の関連画像ファイル（`restored_ID_*`, `user_*`）も物理削除し、アナライザーキャッシュ（`invalidate_analyzer_cache()`）を即座に破棄。

---

## 5. フロントエンド・UI/UXの堅牢化

### 5.1 グローバル関数連携とSPA挙動の安定化
- サイドバーの画像セッション一覧クリックと結果画面の更新関数（`window.updateViewForImageId`）をグローバルに統一。画面遷移なし（SPA）で瞬時に表示を切り替え。
- 変数の多重宣言（`const` 衝突）を排除し、JavaScriptの構文エラーによる画面フリーズを根絶。
